## 1. Abstract

Reddcoin's PoSV kernel is the unmodified ppcoin-v0.3 stake kernel. For an aged
UTXO every kernel input is constant except the block timestamp `nTimeTx`, the
timestamp has **1-second granularity** (no mask), consensus accepts block times
up to **+2 h** in the future, and the stake modifier is coin-fixed. Together these
let an attacker evaluate the kernel at ~7,200 future timestamps per UTXO per tip -
winners the honest wallet (searching only ~60 s backward) never sees - and
future-stamp blocks to push `GetMedianTimePast` forward and lock out honest
stakers (simulated ~ 2.5-5 % of online stake -> 84-100 % of blocks).

This REP is **part 1 of a two-part program**. It ships the **PoSV3 timestamp
hardening** - a strict rule *tightening*, therefore a **soft fork**, deployed via
**BIP9 versionbits** (staker-signaled) with a **BIP8 mandatory-activation
backstop**:

1. **Timestamp mask** - post-activation the coinstake/block time must satisfy
   `(nTime & nStakeTimestampMask) == 0` (`0xf` -> 16-second granularity).
2. **Future-drift reduction** - post-activation the future limit drops from
   `2 h` to `15 s`.
3. **Wallet search parity** (non-consensus) - the staker searches the whole legal
   window at mask granularity, so no winning timestamp is visible to an attacker
   but not to honest stakers.

Effect: the grindable future surface collapses from ~7,200 one-second slots to
**<= 1** masked slot (15 s window < one 16 s slot); the median-manipulation
capture vector is eliminated; the honest/attacker asymmetry drops from ~7,200x to
~1x. PoSV coin-age economics are unchanged.

The residual - a coin-fixed, precomputable modifier - is closed for *fairness* by
change 3 here, and closed *cryptographically* by the sequenced **REP-0004**
per-block modifier **hard fork** (§12). The two are deliberately separate because
they are **opposite fork types** (soft vs hard) and cannot share one BIP9.

## 2. Motivation

### 2.1 The defect (verified against source)

| Enabler | Source | Value |
|---|---|---|
| Kernel preimage - only `nTimeTx` varies for a fixed UTXO | `src/pos/kernel.cpp:418-419` | `modifier||nTimeBlockFrom||nTxPrevOffset||nTimeTxPrev||prevout.n||nTimeTx` |
| 1-second granularity (no mask) | `CheckCoinStakeTimestamp` `src/pos/kernel.cpp:481-484` | `nTimeBlock == nTimeTx` only |
| +2 h future drift | `src/validation.h:106`, `src/validation.cpp:3378` (`MAX_FUTURE_BLOCK_TIME`, `chain.h:25`) | `2*60*60` |
| Coin-fixed modifier (tip-independent for aged coins) | `GetKernelStakeModifier` `src/pos/kernel.cpp:273-353` | walks active chain from coin's block |
| Honest wallet searches only <=60 s backward | `src/wallet/staking.cpp:206-219`, `src/miner.cpp:186-194` | `nMaxStakeSearchInterval = 60` |

Consensus-legal window per tip: `[GetMedianTimePast()+1, now+2h]`
(`validation.cpp:3374`, `:3378`) -> ~7,700 one-second candidates, ~7,200 in the
future and invisible to honest wallets.

### 2.2 Impact
- **Grinding:** headline block 6,547,816 had 1 extra in-window winner at +4,572 s;
  5/17 sampled blocks had >=1 extra.
- **Capture:** future-stamped blocks raise `GetMedianTimePast`, eventually failing
  honest `time > median` checks; the attacker branch then wins by ordinary
  difficulty-weighted trust.

### 2.3 Why mask + drift first, modifier later
The dominant lever is **window-size x granularity**, closed by mask + drift alone -
small, reviewable, precedented (Blackcoin/Clams/eMark), and a clean soft fork.
The modifier change removes long-range *precomputation* but **redefines the kernel
preimage** -> old nodes reject new blocks -> it is a **hard fork** and cannot ride a
BIP9 soft fork. It is therefore split into REP-0004 (§12).

## 3. Specification

Let `M = consensus.nStakeTimestampMask` (mainnet `0xf`). Activation is by
versionbits:

```
PoSV3Active(pindexPrev) := DeploymentActiveAfter(pindexPrev, params, DEPLOYMENT_POSV3)
```

All rules gate on `PoSV3Active(pindexPrev)` and are enforced in the **contextual**
validation path (which has `pindexPrev`). Blocks before activation validate exactly
as today (non-retroactive; no reorg).

**R1 - Coinstake/block timestamp mask (consensus).** For a PoS block on a chain
where `PoSV3Active(pindexPrev)`:
```
(block.nTime & M) == 0        (in addition to the existing block.nTime == coinstake.nTime)
```

**R2 - Future-drift reduction (consensus).** When `PoSV3Active(pindexPrev)`:
```
reject if  block.nTime > adjustedNow + 15     (else legacy 7200)
```
Enforced in `ContextualCheckBlockHeader`, replacing the `MAX_FUTURE_BLOCK_TIME`
comparison at `validation.cpp:3378`. The context-free bound in `CheckBlockHeader`
(`:3184`) stays at +2 h - it has no `pindexPrev` and so cannot be deployment-gated.

**R3 - Header-only mask (consensus, DoS/fake-stake).** A PoS block header on an
active chain must satisfy `(block.nTime & M) == 0`, checked in
`ContextualCheckBlockHeader` before kernel/signature work. Because `nTime` is a
header field, this is the *same* check as R1 rather than a second one (§4.3/§4.5).

**R4 - Miner/staker production (policy).** When active, produce coinstakes and
headers only at masked timestamps.

**R5 - Wallet search parity (policy, non-consensus).** When active, enumerate
every masked timestamp in `[GetMedianTimePast()+1, now+15]` (step `M+1`), not just
60 s backward.

### 4.3 Timestamp mask (R1) - `ContextualCheckBlockHeader`, `src/validation.cpp`

> **Function map (verified against `87df3a9`).** The three timestamp call sites are
> in three *different* functions, and it matters which one gets the rule:
>
> | Lines | Function | Has `pindexPrev`? | Sees `vtx`? |
> |---|---|---|---|
> | 3172-3189 | `CheckBlockHeader` (context-free) | no | no |
> | 3353-3390 | `ContextualCheckBlockHeader` | yes | no (takes `CBlockHeader`) |
> | 3399+ | `ContextualCheckBlock` | yes | yes (takes `CBlock`) |
>
> The median-time check (`:3374`) and the `MAX_FUTURE_BLOCK_TIME` check (`:3378`)
> are both in **`ContextualCheckBlockHeader`**, not in `ContextualCheckBlock`. The
> `FutureDrift` check at `:3184` is in **`CheckBlockHeader`**, which has no
> `pindexPrev` and therefore cannot consult a deployment at all.

`CheckCoinStakeTimestamp` (`pos/kernel.cpp:481-484`) is **unchanged** - it keeps the
context-free `nTimeBlock == nTimeTx` equality. The mask, being deployment-gated,
goes into `ContextualCheckBlockHeader` next to the median/drift checks (`:3374`,
`:3378`), where `pindexPrev` is in scope. Because the block time is a header field,
one check there covers both the headers-first path and full blocks - R1 and R3 are
therefore the *same* check, stated once (§4.5), not two checks in two functions.

```cpp
    // Existing: median-time-past (:3374) and future-drift (:3378) checks ...

    // REP-0003 (R1/R3): quantise the stake timestamp once PoSV3 is active. Reduces
    // the grindable window to <= 1 slot per tip.
    if (IsPoSEraBlock(pindexPrev, consensusParams) && IsPoSV3Active(pindexPrev, consensusParams)) {
        if ((block.GetBlockTime() & consensusParams.nStakeTimestampMask) != 0)
            return state.Invalid(BlockValidationResult::BLOCK_INVALID_HEADER,
                                 "time-not-masked", "block timestamp not on stake-mask boundary");
    }
```

> **Do not gate on `block.IsProofOfStake()` here.** That expression compiles in both
> functions but means two different things:
>
> * `CBlock::IsProofOfStake()` (`primitives/block.h:139-142`) = `vtx.size() > 1 &&
>   vtx[1]->IsCoinStake()` - the real coinstake test.
> * `CBlockHeader::IsProofOfStake()` (`primitives/block.cpp:31-34`) =
>   `nVersion > POW_BLOCK_VERSION` (`POW_BLOCK_VERSION == 2`,
>   `primitives/transaction.h:19`) - a test of an **attacker-chosen version field**.
>
> `ContextualCheckBlockHeader` takes a `CBlockHeader`, so it silently gets the second
> one. The existing version floor (`:3382-3385`, which requires `nVersion >= 5` once
> `DEPLOYMENT_DEV` is active) does make it true in practice - but that check runs
> *after* `:3374`/`:3378`, so a rule inserted next to them cannot rely on it having
> run. Use the tree's own PoS-era predicate instead:
> ```cpp
> // Mirrors validation.cpp:1794 and :1931, which both use strict `>`.
> inline bool IsPoSEraBlock(const CBlockIndex* pindexPrev, const Consensus::Params& params) {
>     return pindexPrev != nullptr && pindexPrev->nHeight + 1 > params.nLastPowHeight;
> }
> ```
> Note the comparison is `>` against `nLastPowHeight`, not `>=`.

### 4.4 Future-drift reduction (R2) - `src/chain.h` + `src/validation.cpp`

`src/chain.h` (lines 25-26) - add the PoSV3 limit alongside the two existing
constants. Note `MAX_FUTURE_STAKE_TIME` on the adjacent line: it is a *backward*
tolerance used by the miner (§4.6), not a future bound, despite the name. It is not
changed by this REP, but §4.6 interacts with it.
```cpp
static constexpr int64_t MAX_FUTURE_BLOCK_TIME = 2 * 60 * 60;        // legacy, unchanged
static constexpr int64_t MAX_FUTURE_STAKE_TIME = 3 * 60;             // existing, unchanged
static constexpr int64_t MAX_FUTURE_BLOCK_TIME_POSV3 = 15;           // REP-0003
```

**Contextual header check** (`ContextualCheckBlockHeader`) - `validation.cpp:3377-3379`, current:
```cpp
    if (block.GetBlockTime() > nAdjustedTime + MAX_FUTURE_BLOCK_TIME)
        return state.Invalid(BlockValidationResult::BLOCK_TIME_FUTURE, "time-too-new", "block timestamp too far in the future");
```
proposed:
```cpp
    const int64_t maxFuture = (IsPoSEraBlock(pindexPrev, consensusParams) &&
                               IsPoSV3Active(pindexPrev, consensusParams))
                              ? MAX_FUTURE_BLOCK_TIME_POSV3 : MAX_FUTURE_BLOCK_TIME;
    if (block.GetBlockTime() > nAdjustedTime + maxFuture)
        return state.Invalid(BlockValidationResult::BLOCK_TIME_FUTURE, "time-too-new", "block timestamp too far in the future");
```
> Uses `nAdjustedTime` - the parameter `ContextualCheckBlockHeader` already receives
> (`:3353`) - rather than calling `GetAdjustedTime()` again, so the bound is computed
> from the same clock reading as the check it replaces.

**Context-free header check** - `validation.cpp:3184`, inside `CheckBlockHeader`
(`:3172-3189`) - **left unchanged** (keeps the loose
`FutureDrift(GetAdjustedTime())`, defined `validation.h:106` as `+2 h`). That
function has no `pindexPrev`, so it cannot consult the deployment at all; the tighter
15 s bound is enforced contextually above. The loose check remains a valid superset
gate.

### 4.5 Header-level enforcement (R3) - same site as §4.3

R3 is not a separate code change. Because `block.nTime` is a header field and
`ContextualCheckBlockHeader` runs on the headers-first path *and* ahead of every full
block, the single mask check in §4.3 already provides the fake-stake DoS property R3
asks for: a mis-masked PoS header is rejected at `:3374`-adjacent code, before any
kernel or signature work.

Two consequences worth stating explicitly, because the earlier draft of this REP
split R1 and R3 across two functions and would have produced a duplicated check:

* The rejection reason for a mis-masked block is `time-not-masked` with
  `BLOCK_INVALID_HEADER` (not `bad-cs-time` / `BLOCK_CONSENSUS`) - it is detected at
  header level, so tests must assert that reason. `ContextualCheckBlock` (`:3399`)
  needs no PoSV3 change at all.
* `CheckCoinStakeTimestamp` continues to enforce `block.nTime == coinstake.nTime`
  context-free, so masking the header time transitively masks the coinstake time.
  No separate coinstake-side mask rule is required.

### 4.6 Miner / staker - `src/miner.cpp`, `src/wallet/staking.cpp`

**Miner block time** (`miner.cpp:186-187`, `pblock->nTime` `:149`, `UpdateTime` `:65`)
- mask when active (`pindexPrev` is the tip, in scope from `:152`):
```cpp
    txCoinStake.nTime = GetAdjustedTime();
    if (IsPoSV3Active(pindexPrev, chainparams.GetConsensus()))
        txCoinStake.nTime &= ~(uint32_t)chainparams.GetConsensus().nStakeTimestampMask;
    int64_t nSearchTime = txCoinStake.nTime;
```

> **Masking rounds *down*, and there is an existing lower bound just below.**
> `miner.cpp:196` gates the produced coinstake on
> ```cpp
> txCoinStake.nTime >= std::max(pindexPrev->GetMedianTimePast()+1,
>                               pindexPrev->GetBlockTime() - MAX_FUTURE_STAKE_TIME)
> ```
> Truncating `nTime` by up to 15 s can carry it below `GetMedianTimePast()+1`, in
> which case the staker discards a coinstake that was legal a moment earlier - a
> silent loss of blocks near the median boundary, worst at low block intervals.
> The mask must therefore never be applied below that floor. Either clamp:
> ```cpp
>     const int64_t floor_t = std::max(pindexPrev->GetMedianTimePast() + 1,
>                                      pindexPrev->GetBlockTime() - MAX_FUTURE_STAKE_TIME);
>     if (IsPoSV3Active(pindexPrev, chainparams.GetConsensus())) {
>         const uint32_t m = chainparams.GetConsensus().nStakeTimestampMask;
>         uint32_t t = txCoinStake.nTime & ~m;
>         if ((int64_t)t < floor_t) t += (m + 1);   // step up to the next legal slot
>         txCoinStake.nTime = t;
>     }
> ```
> or let the R5 search below choose the slot and drop the truncation here entirely.
> The R5 snippet already rounds its low bound *up* (`lo = (medianPlus1 + mask) & ~mask`);
> the miner path is the one that needs the same treatment.

**Staker search parity (R5)** - `wallet/staking.cpp:206-219` - full-window,
mask-aligned scan. In the current code `pindexPrev` is declared *inside* the search
loop (`:218`); it must be hoisted above the window computation:
```cpp
    const Consensus::Params& params = consensusParams;
    CBlockIndex* pindexPrev = chainstate->m_chain.Tip();            // hoisted from :218
    const bool  posv3 = IsPoSV3Active(pindexPrev, params);
    const int   mask  = posv3 ? params.nStakeTimestampMask : 0;
    const int   step  = mask + 1;                                   // 16 s (or 1 s legacy)
    const int64_t maxFuture = posv3 ? MAX_FUTURE_BLOCK_TIME_POSV3 : 0;

    const int64_t medianPlus1 = pindexPrev->GetMedianTimePast() + 1;
    int64_t hi = (txNew.nTime + maxFuture) & ~(int64_t)mask;        // top of legal window
    int64_t lo = (medianPlus1 + mask) & ~(int64_t)mask;            // round up to a slot
    if (!posv3) { hi = txNew.nTime; lo = txNew.nTime - std::min<int64_t>(nSearchInterval, 60); }

    bool fKernelFound = false;
    for (int64_t t = hi; t >= lo && !fKernelFound; t -= step) {
        if (header.GetBlockTime() + params.nStakeMinAge > t) continue;   // min age
        COutPoint prevoutStake = pcoin.outpoint;
        uint256 hashProofOfStake;
        if (CheckStakeKernelHash(chainstate, pindexPrev, nBits, header,
                                 prevoutStake.n, tx, prevoutStake,
                                 (unsigned int)t, hashProofOfStake)) {
            txNew.nTime = t;                                          // masked, in-window
            fKernelFound = true;
            // ... existing coinstake assembly ...
        }
    }
```
> `CheckStakeKernelHash`'s `nTimeTx` parameter is `unsigned int` (`pos/kernel.h:33`),
> so the `int64_t` loop variable needs the explicit cast shown; the existing call at
> `:219` passes `txNew.nTime - n`, which is already unsigned.
>
> The 5th argument is `nTxPrevOffset`, and both the current code and this snippet pass
> `prevoutStake.n` for it. That is the pre-existing offset-equals-vout-index quirk
> retired by [REP-0004](rep-0004.md); it is preserved verbatim here so this REP stays
> a pure timestamp change.
>
> R5 is local policy only - it changes *which* legal slots this node tries,
> closing the "invisible to honest wallet" gap. Per-tip cost ~20 SHA-256d.

## 5. Unit tests - `src/test/pos_timestamp_tests.cpp` (new)

Two groups: (a) pure mask/drift arithmetic; (b) versionbits gating (active vs
inactive) using custom regtest params.

```cpp
// Copyright (c) 2026 The Reddcoin developers - MIT.
#include <chain.h>
#include <chainparams.h>
#include <consensus/params.h>
#include <deploymentstatus.h>
#include <pos/kernel.h>
#include <test/util/setup_common.h>
#include <boost/test/unit_test.hpp>

static const int MASK = 0xf;

BOOST_FIXTURE_TEST_SUITE(pos_timestamp_tests, TestingSetup)

BOOST_AUTO_TEST_CASE(mask_constant_and_alignment)
{
    BOOST_CHECK_EQUAL(MASK + 1, 16);
    for (int i = 0; i < 64; ++i) {
        int64_t t = 1793318400 + i;
        int64_t aligned = t & ~int64_t(MASK);
        BOOST_CHECK_EQUAL(aligned & MASK, 0);
        BOOST_CHECK(aligned <= t && t - aligned <= MASK);
    }
}

BOOST_AUTO_TEST_CASE(drift_constants)
{
    BOOST_CHECK_EQUAL(MAX_FUTURE_BLOCK_TIME_POSV3, 15);
    BOOST_CHECK_EQUAL(MAX_FUTURE_BLOCK_TIME, 2 * 60 * 60);
}

// Build a fake index chain and toggle DEPLOYMENT_POSV3 via a params copy.
BOOST_AUTO_TEST_CASE(deployment_gates_mask_and_drift)
{
    Consensus::Params active   = Params().GetConsensus();
    active.nStakeTimestampMask = MASK;
    active.vDeployments[Consensus::DEPLOYMENT_POSV3].nStartTime =
        Consensus::BIP9Deployment::ALWAYS_ACTIVE;

    Consensus::Params inactive = active;
    inactive.vDeployments[Consensus::DEPLOYMENT_POSV3].nStartTime =
        Consensus::BIP9Deployment::NEVER_ACTIVE;

    CBlockIndex prev;                              // minimal tip stub
    BOOST_CHECK( DeploymentActiveAfter(&prev, active,   Consensus::DEPLOYMENT_POSV3));
    BOOST_CHECK(!DeploymentActiveAfter(&prev, inactive, Consensus::DEPLOYMENT_POSV3));

    // With gate ON: only masked times pass the R1 predicate; drift bound = 15.
    auto masked_ok = [&](int64_t t){ return (t & active.nStakeTimestampMask) == 0; };
    BOOST_CHECK( masked_ok(1793318400 & ~int64_t(MASK)));
    for (int i = 1; i <= MASK; ++i) BOOST_CHECK(!masked_ok((1793318400 & ~int64_t(MASK)) + i));
}

BOOST_AUTO_TEST_CASE(coinstake_equality_unchanged)
{
    // CheckCoinStakeTimestamp still rejects block!=coinstake in both eras.
    BOOST_CHECK( CheckCoinStakeTimestamp(1000, 1000));
    BOOST_CHECK(!CheckCoinStakeTimestamp(1000, 1016));
}

BOOST_AUTO_TEST_SUITE_END()
```

## 6. Functional test - `test/functional/feature_posv3_timestamp.py` (new)

Uses `-vbparams=posv3:START:TIMEOUT` to drive activation deterministically, plus
the framework's `create_block(ntime=...)`, `sign_block`, `advance_time_for_pos`.

```python
#!/usr/bin/env python3
"""PoSV3 timestamp hardening: BIP9 activation, mask, drift (REP-0003)."""
from test_framework.test_framework import BitcoinTestFramework
from test_framework.blocktools import create_block, sign_block
from test_framework.util import assert_equal, advance_time_for_pos
from test_framework.test_node import TestNode as TN

MASK, STEP = 0xf, 16

class PosV3TimestampTest(BitcoinTestFramework):
    def set_test_params(self):
        self.num_nodes = 1
        self.setup_clean_chain = False                 # aged-coin cache
        self.START = 2_000_000_000                     # scheduled activation (mocktime domain)
        self.extra_args = [[f"-vbparams=posv3:{self.START}:{self.START + 10_000_000}"]]

    def skip_test_if_missing_module(self):
        self.skip_if_no_wallet()

    def run_test(self):
        node, addr = self.nodes[0], TN.PRIV_KEYS[0].address

        # (1) DEFINED/STARTED (pre-activation): 1-second timestamps still valid.
        advance_time_for_pos(node, seconds=600)
        h0 = node.getblockcount()
        node.generatetoaddress(1, addr)
        assert_equal(node.getblockcount(), h0 + 1)
        assert node.getblockchaininfo()["softforks"]["posv3"]["bip9"]["active"] is False

        # (2) Signal + advance past the window until posv3 is ACTIVE.
        node.setmocktime(self.START + 32)
        for _ in range(self.mocked_window()):          # mine enough signaling blocks
            advance_time_for_pos(node, seconds=STEP)
            try: node.generatetoaddress(1, addr)
            except Exception: pass
        assert node.getblockchaininfo()["softforks"]["posv3"]["bip9"]["active"] is True

        # (3) Active: node-produced blocks are mask-aligned (R1/R4).
        for _ in range(6):
            advance_time_for_pos(node, seconds=STEP)
            try: bh = node.generatetoaddress(1, addr)[0]
            except Exception: continue
            assert_equal(node.getblockheader(bh)["time"] & MASK, 0)

        # (4) Negative: masked accepted, off-slot rejected.
        tmpl = node.getblocktemplate({"rules": ["segwit"], "capabilities": ["coinstake"]})
        good = sign_block(create_block(tmpl=tmpl, ntime=tmpl["curtime"] & ~MASK), TN.PRIV_KEYS[0].key)
        assert_equal(node.submitblock(good.serialize().hex()), None)
        bad = sign_block(create_block(tmpl=tmpl, ntime=(tmpl["curtime"] & ~MASK) + 1), TN.PRIV_KEYS[0].key)
        assert node.submitblock(bad.serialize().hex()) in ("bad-cs-time", "time-not-masked", "high-hash")

        # (5) Negative: future-stamp > 15 s rejected.
        best = node.getblockheader(node.getbestblockhash())["time"]
        far = sign_block(create_block(tmpl=tmpl, ntime=(best + 3600) & ~MASK), TN.PRIV_KEYS[0].key)
        assert node.submitblock(far.serialize().hex()) in ("time-too-new", "bad-cs-time")

    def mocked_window(self):
        # getblockchaininfo does NOT expose the confirmation window in this tree, so
        # it cannot be read back over RPC - hardcode regtest's nMinerConfirmationWindow
        # from chainparams and assert it, rather than silently defaulting to 2016.
        return 2 * REGTEST_CONFIRMATION_WINDOW + 10

if __name__ == "__main__":
    PosV3TimestampTest().main()
```

## 7. Functional test - `test/functional/feature_posv3_stakegrind.py` (new)

Anti-grinding / fake-stake regression. Runs with posv3 **always active**
(`-vbparams=posv3:0:...` i.e. `ALWAYS_ACTIVE`) to focus on the security
properties. Same body and assertion table as before; only the activation control
changes.

```python
#!/usr/bin/env python3
"""PoSV3 anti-grinding / fake-stake regression (REP-0003).

Reproduces the stake-grinding threat model - grind nTimeTx across the window, and
future-stamp to push GetMedianTimePast - and asserts both are neutralised."""
from test_framework.test_framework import BitcoinTestFramework
from test_framework.blocktools import create_block, sign_block
from test_framework.util import assert_greater_than, advance_time_for_pos
from test_framework.test_node import TestNode as TN

MASK, STEP, DRIFT, TWO_HOURS = 0xf, 16, 15, 7200

class PosV3StakeGrindTest(BitcoinTestFramework):
    def set_test_params(self):
        self.num_nodes = 2
        self.setup_clean_chain = False
        self.extra_args = [["-vbparams=posv3:-1:9999999999"],   # -1 => ALWAYS_ACTIVE
                           ["-vbparams=posv3:-1:9999999999"]]

    def skip_test_if_missing_module(self):
        self.skip_if_no_wallet()

    def run_test(self):
        honest, attacker = self.nodes
        self.connect_nodes(0, 1)
        addr = TN.PRIV_KEYS[0].address
        advance_time_for_pos(self.nodes, seconds=600)

        tip = honest.getbestblockhash()
        now = honest.getblockheader(tip)["time"]

        # A. WINDOW: legal FUTURE masked slots <= 1.
        hi = (now + DRIFT) & ~MASK
        lo = (now + STEP) & ~MASK
        slots = 0 if hi < lo else (hi - lo)//STEP + 1
        assert slots <= 1, slots
        assert_greater_than(TWO_HOURS, slots * STEP)      # vs legacy 7200-wide surface

        # B. FAKE-STAKE: future-stamp beyond drift rejected.
        tmpl = attacker.getblocktemplate({"rules": ["segwit"], "capabilities": ["coinstake"]})
        for ahead in (16, 64, 3600, TWO_HOURS):
            blk = sign_block(create_block(tmpl=tmpl, ntime=(now + ahead) & ~MASK), TN.PRIV_KEYS[0].key)
            res = attacker.submitblock(blk.serialize().hex())
            assert res is not None and res in ("time-too-new", "bad-cs-time"), (ahead, res)

        # C. GRINDING: off-slot timestamps rejected.
        for off in range(1, MASK + 1):
            blk = sign_block(create_block(tmpl=tmpl, ntime=(now & ~MASK) + STEP + off), TN.PRIV_KEYS[0].key)
            assert attacker.submitblock(blk.serialize().hex()) is not None

        # D. MEDIAN LOCKOUT: mediantime cannot be pushed ahead of wall time.
        assert ((now + DRIFT) & ~MASK) - now <= DRIFT
        pre = honest.getblockchaininfo()["mediantime"]
        for _ in range(6):
            advance_time_for_pos(self.nodes, seconds=STEP)
            try: honest.generatetoaddress(1, addr)
            except Exception: pass
        self.sync_all()
        post = honest.getblockchaininfo()["mediantime"]
        assert_greater_than(post, pre)
        assert post <= honest.getblockheader(honest.getbestblockhash())["time"]

        # E. PARITY: honest node wins whenever any legal slot wins (R5).
        h = honest.getblockcount()
        for _ in range(20):
            advance_time_for_pos(self.nodes, seconds=STEP)
            try: honest.generatetoaddress(1, addr); break
            except Exception: continue
        assert_greater_than(honest.getblockcount() + 1, h)

if __name__ == "__main__":
    PosV3StakeGrindTest().main()
```

| Test | Property | Rule |
|---|---|---|
| A | <= 1 legal future slot | R1+R2 kill grinding surface |
| B | future-stamp > 15 s rejected | R2 kills fake-stake / median push |
| C | off-mask rejected | R1 |
| D | `mediantime` can't outrun wall time | capture neutralised |
| E | honest wins whenever any legal slot wins | R5 parity - no invisible winners |

> Add a p2p variant (submit via `P2PInterface.send_message(msg_block)`) asserting
> the header-only mask (R3) drops a mis-masked block before it connects, without
> the RPC `submitblock` convenience - the true fake-stake DoS path.

## 8. Fork implications - BIP9 soft fork with BIP8 backstop

### 8.1 Classification
R1-R3 are strict **tightenings**: post-activation valid blocks are a subset of
pre-activation valid blocks. A fully-upgraded network's blocks remain valid under
the old rules (a 16-aligned time is a valid 1-second time; +15 s is within +2 h),
so legacy nodes **follow the new-rule chain**. This is a **soft fork** - and on a
PoS chain the signalers are **stakers**.

### 8.2 Why BIP9 is the right vehicle here
BIP9's signaling threshold **auto-enforces the safety property this change needs**:
the mask makes ~15/16 of *legacy-format* blocks invalid, so activation must not
occur until a staking supermajority is ready. BIP9 will not `LOCK_IN` until
>= threshold of blocks (over `nMinerConfirmationWindow`) signal bit 5 - precisely
"don't flip the mask until the stakers are ready." No manual flag-day risk
assessment required.

### 8.3 The stall risk and the BIP8 backstop
Plain BIP9 can reach `FAILED` at `nTimeout` if dormant/abandoned stake keeps
signaling below threshold - unacceptable for a *security* fix that must ship. We
therefore set `lockinontimeout = true` (mechanism from **REP-0002**): if the
threshold is not met by `nTimeout`, the deployment `LOCKS_IN` anyway (BIP8
lot=true), guaranteeing activation by a known deadline while still activating
*early* if stakers adopt quickly. This is the recommended posture for consensus
**security** fixes.

### 8.4 Non-retroactivity & reorg safety
All predicates gate on `DeploymentActiveAfter(pindexPrev, ...)`. Pre-activation
blocks validate exactly as today: no historical block is invalidated, no reorg is
triggered, IBD/reindex of history is unchanged.

### 8.5 Residual split/grief scenarios

| Scenario | Outcome | Handling |
|---|---|---|
| Threshold reached, node upgraded | Clean `LOCKED_IN -> ACTIVE`; legacy nodes follow | Standard BIP9 |
| Threshold not reached by timeout | BIP8 forces `LOCKED_IN`; then ACTIVE | `lockinontimeout=true` |
| Un-upgraded staker mints after activation | ~15/16 of its blocks orphaned by upgraded majority | Standard soft-fork incentive to upgrade |
| Attacker future-stamps across activation | Blocked: rule gates on chain state at `pindexPrev`, tight 15 s applies once active | R2 |
| Large minority never upgrades | Minority builds legacy chain; legacy *nodes* ride the heavier (upgraded) chain - safe unless the un-upgraded *stake* majority exceeds the upgraded stake | Signaling telemetry + set `nTimeout`/comms so supermajority upgrades before lock-in |

### 8.6 Contrast with the sequenced modifier change (REP-0004)
The per-block modifier **redefines the kernel preimage**: a block new nodes accept
has a different `hashProof` under old rules -> old nodes **reject** it -> **hard
fork** (bilateral). It therefore cannot ride this BIP9 (doing so would forfeit the
soft-fork guarantees) and is shipped separately with height/flag-day activation
(§12).

## 10. Backwards compatibility
- **Consensus:** breaking for un-upgraded stakers post-activation (intended);
  non-staking legacy nodes stay compatible (§8.1).
- **RPC/tooling:** `getblocktemplate` `curtime`/`mintime` unchanged; produced
  coinstake time is mask-aligned once active. Third-party stakers must align
  `nTime` to `M+1` - release-note it. `getblockchaininfo` reports `posv3` under
  `softforks` (there is no `getdeploymentinfo` RPC in this tree).
- **Staking stats:** with a 16 s slot the per-wall-second hash rate changes ~1/16;
  divide `netstakeweight`/`expectedtime` helpers by `nStakeTimestampMask + 1`
  (cf. Blackcoin `rpc/blockchain.cpp` `result *= nStakeTimestampMask + 1`).
- **History/explorers:** unaffected (non-retroactive).

## 11. Residual risk (closed for fairness here; cryptographically in REP-0004)
Mask + drift closes the **capture** vector and cuts the attacker's block-production
advantage from ~7,200x to ~1x; **R5** removes the honest/attacker visibility gap.
The modifier remains coin-fixed, so the ~20-slot *total* window per tip is
precomputable - but with R5 honest stakers enumerate the same slots (no fairness
gap), and per-tip recomputation (~every 60 s) makes precomputation worthless. Full
*cryptographic* removal of precomputation is REP-0004 (§12).

## 12. Sequenced follow-up - REP-0004: per-block stake modifier (HARD fork)

**Committed as part 2 of this program**, now specified in full in its own
proposal: **[REP-0004 - Per-block Stake Modifier](rep-0004.md)**. Summary:

- **Change:** replace the legacy (coin-fixed) modifier with a per-block, prevout-bound
  modifier - `nStakeModifierV2 = Hash(prevoutStake || prevModifier)` (PIVX-style;
  Reddcoin already stores `prevoutStake` on the index, `chain.h:219`) - and hash the
  tip's per-block modifier in the kernel. Reddcoin's PoSV coin-age weight is retained.
- **Why separate:** it redefines `CheckStakeKernelHash`'s preimage, so old nodes
  reject new-rule blocks -> **bilateral hard fork**, incompatible with this REP's
  BIP9 soft-fork model. Height flag day + checkpoint; mandatory upgrade.
- **Sequencing rationale:** REP-0003 removes the *exploitable* capture vector now,
  at low risk (soft fork); REP-0004 then removes the residual precomputation edge
  with a higher-risk kernel change, on its own schedule. See [REP-0004](rep-0004.md)
  for the full spec, migration/reindex plan, and the chain-split test that proves
  the hard fork.
